---
title: Internationalisation
description: Contenu de formulaire localisé, chrome du builder localisé, et messages de validation sensibles à la locale.
---

FormKrafter sépare deux couches d'i18n — et ne devine jamais la langue du navigateur : l'hôte décide, la lib suit.

## Contenu du formulaire (ce que les auteurs écrivent)

Tout label, placeholder, message ou liste d'options d'un spec peut être une chaîne simple **ou** un objet par locale :

```json
{ "label": { "en": "Full name", "fr": "Nom complet" } }
```

Passez `locale` à `<fk-form-render>` pour le résoudre. Dans le builder, passez `locales={['en','fr']}` pour obtenir un sélecteur de langue d'édition — les champs du panel lisent et écrivent alors la langue sélectionnée.

Les messages de validation se résolvent par la même cascade : message de l'auteur (optionnellement localisé) → défauts localisés intégrés (`en` et `fr` fournis, extensibles avec `registerValidationMessages('de', { … })`).

## Chrome du builder (ce que vos utilisateurs voient)

Palette, property panel, boutons, noms de bricks — environ 90 clés :

```ts
import { setFkTranslations, frFkTranslations } from '@streamline-pulse/formkrafter-wc'

setFkTranslations(frFkTranslations)   // avant le montage ; re-montez pour changer à chaud
```

L'anglais est le défaut ; le français est fourni dans le package ; enregistrez votre propre dictionnaire pour d'autres langues.
