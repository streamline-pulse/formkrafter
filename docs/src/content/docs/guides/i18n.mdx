import { Aside, Tabs, TabItem, CardGrid, LinkCard } from '@astrojs/starlight/components'

FormKrafter separates two things most libraries conflate: the **content of a
form** (authored by whoever built it) and the **chrome of the builder** (the UI
your users click through). They are localized independently, and neither ever
sniffs the browser language — the host decides, the library follows.

## Layer 1 — form content

Any label, placeholder, message or option list in a spec may be a plain string
**or** an object keyed by locale:

```json title="A localized label"
{ "label": { "en": "Full name", "fr": "Nom complet" } }
```

Pass `locale` to the renderer to resolve it:

<Tabs syncKey="framework">
  <TabItem label="React">
    ```tsx
    <FkFormRender spec={spec} locale="fr" />
    ```
  </TabItem>
  <TabItem label="Vue">
    ```vue
    <FkFormRender :spec="spec" locale="fr" />
    ```
  </TabItem>
  <TabItem label="Web Components">
    ```js
    document.querySelector('fk-form-render').locale = 'fr'
    ```
  </TabItem>
</Tabs>

In the builder, pass `locales` to get an edit-language selector — panel fields
then read and write the selected language:

```tsx
<FkFormBuilder locales={['en', 'fr']} />
```

<Aside type="tip">
Validation messages resolve through the same mechanism, so
`{ "message": { "en": "Required", "fr": "Obligatoire" } }` works exactly like a
label. See [validation](../validation/#messages-and-locales).
</Aside>

## Layer 2 — builder chrome

The palette, property panel, buttons and brick names are about 90 translation
keys. English is built in and French ships in the package:

```ts title="Before mounting the builder"
import { setFkTranslations, frFkTranslations } from '@streamline-pulse/formkrafter-wc'

setFkTranslations(frFkTranslations)
```

For any other language, pass your own dictionary — it is merged over the
built-in English, so a partial translation is valid:

```ts
setFkTranslations({
  'palette.search': 'Bausteine suchen…',
  'panel.validation': 'Validierung',
})
```

<Aside type="caution">
Do **not** remount the components to switch language — that wipes the form
being filled or built. Call `setFkTranslations` first, then change the
`locale` prop: the renderer re-resolves its labels and the builder re-renders
its toolbar, palette and panel in place.
</Aside>

## Choosing a locale

Because nothing is automatic, the choice is explicitly yours — a URL segment, a
user preference, a cookie. A typical wiring:

```tsx title="Locale from the route"
import { setFkTranslations, frFkTranslations } from '@streamline-pulse/formkrafter-wc'

const locale = useRouteLocale()            // your router, your rule
if (locale === 'fr') setFkTranslations(frFkTranslations)

return <FkFormRender spec={spec} locale={locale} />
```
