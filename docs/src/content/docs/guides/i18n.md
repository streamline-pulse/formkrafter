---
title: Internationalization
description: Localized form content, localized builder chrome, and locale-aware validation messages.
---

FormKrafter separates two layers of i18n — and never sniffs the browser language: the host decides, the lib follows.

## Form content (what authors write)

Any label, placeholder, message or option list in a spec can be a plain string **or** a per-locale object:

```json
{ "label": { "en": "Full name", "fr": "Nom complet" } }
```

Pass `locale` to `<fk-form-render>` to resolve it. In the builder, pass `locales={['en','fr']}` to get an edit-language selector — panel fields then read and write the selected language.

Validation messages resolve through the same cascade: the author's message (optionally localized) → built-in localized defaults (`en` and `fr` shipped, extend with `registerValidationMessages('de', { … })`).

## Builder chrome (what your users see)

Palette, property panel, buttons, brick names — about 90 keys:

```ts
import { setFkTranslations, frFkTranslations } from '@streamline-pulse/formkrafter-wc'

setFkTranslations(frFkTranslations)   // before mounting; re-mount to switch live
```

English is the default; French ships in the package; register your own dictionary for other languages.
